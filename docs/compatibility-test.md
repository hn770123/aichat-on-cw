# ブラウザー互換性テスト記録

## 目的

iOS 9 Safari 相当環境と現行デスクトップブラウザーで、認証から会話削除までの主要操作、表示安全性、障害時の復帰を確認します。この文書は実施手順と結果の記録を兼ねます。

## 今回の確認結果（2026-09-18）

| 対象 | 結果 | 備考 |
| --- | --- | --- |
| Workers ランタイム統合テスト | 合格 | `npm test`、23 テストを Miniflare 上で実行 |
| TypeScript 型検査 | 合格 | `npm run typecheck` |
| ES5 静的解析 | 合格 | `npm run lint`。`public/app.js` を ECMAScript 5 として解析 |
| iOS 9 実機 / BrowserStack iOS 9 Safari | 未実施 | この実行環境には実機および BrowserStack の認証情報がないため。リリース前に下記手順を実施すること |
| 現行 Chrome / Safari / Firefox | 未実施 | GUI ブラウザーを利用できない実行環境のため。リリース前に下記手順を実施すること |

未実施項目を合格として扱わないでください。担当者は実施後に対象端末、OS、ブラウザー、実施日、結果、課題を「実機・サービス確認記録」へ追記します。

## テスト前提

1. 本番と同等のステージング Worker、Workers AI、D1 を用意する。
2. D1 マイグレーションを適用し、テスト専用の Basic 認証 Secret を登録する。
3. HTTPS URL、Workers AI/D1 の利用量、Worker ログを確認できる状態にする。
4. BrowserStack を使う場合は **iPhone / iOS 9 / Safari** を選び、実機相当セッションで確認する。
5. テスト用の会話だけを使用し、システムプロンプトや本文へ秘密情報を入力しない。

## 主要操作チェックリスト

各項目を `合格`、`不合格`、`未実施` のいずれかで記録します。

| 項目 | 期待結果 |
| --- | --- |
| 未認証アクセス | Basic 認証が要求され、画面や API の内容が表示されない |
| 正しい認証 | チャット画面が表示され、モデル一覧と履歴が読み込まれる |
| 履歴がない初期表示 | 新規会話フォームが表示され、空の会話は自動作成されない |
| 新規会話 | モデルとシステムプロンプトを指定して作成できる |
| メッセージ送信 | 処理中表示と二重送信防止が働き、利用者・AI の発言が順番に表示される |
| 履歴再表示 | 作成時のモデル、システムプロンプト、全メッセージが再表示される |
| 会話削除 | 確認ダイアログ後に削除され、履歴から消える |
| 履歴開閉 | 開閉ボタンで履歴が表示・非表示になり、主要操作を妨げない |
| ソフトウェアキーボード | 表示中も入力欄と送信ボタンへスクロールして到達できる |
| 長文・日本語・絵文字・改行 | 入力内容が欠落せず、レイアウトが操作不能にならない |
| HTML 文字列 | `<script>alert(1)</script>` などが文字列として表示され、実行されない |
| 低速回線 | 処理中であることが通知され、完了後に操作可能へ戻る |
| オフライン | 日本語の通信エラーが表示され、入力内容を保持したまま再送できる |
| AI エラー | 一般化されたエラーが表示され、処理中状態が解除される |
| アクセシビリティ | 状態通知が読み上げ対象となり、ラベルとフォーカス順が理解できる |
